# UI contract

**Owner:** UI / interaction engineering
**Audience:** the visual designer working in `src/css/**` (see §1.2 and §8 — the three root
stylesheets are generated, do not edit them), and anyone touching `app.js` or `src/**`.
**Status:** current as of the render-architecture rebuild. Everything below is *implemented*,
not proposed.

This document is the handover. It states the DOM the UI layer produces, every class and state
class it relies on, the custom properties it reads, the animation seam and its event shape, and
the work that was deliberately left undone.

**Every one of these is in the `scripts/build.mjs` copy list.** Adding a module without adding
it there produces a 404 in `dist/`. `npm run build` prints the file count as a cheap check.

#### The rule about numbers

`src/glossary.js` has always described itself as the single source of rules copy, and it was —
for the *wording*. It was not for the *numbers*: those were typed in, and by the time the
armour divisor had moved 4 → 5, the breach ceiling had stopped applying to undefended lanes
and the opening refresh had gone 1 card → 2, the glossary, the pre-match dialog, the mulligan
panel, the seam tooltip and the deck analysis were all describing a game the engine no longer
played. The open-lane definition was the reverse of the truth.

So: **no screen may contain a literal that also exists in `match-engine.js`.** Import it, or
import a sentence built from it in `src/rules-copy.js`. That includes defensive-looking
fallbacks — `engine.STARTING_CORE ?? 20` was a second copy of the constant that would have
gone on quietly drawing a 20-segment Core bar for a game that had stopped starting at 20.
`tests/rules-copy.test.mjs` re-derives every printed claim from `armourBreach`, the draw
schedule and `resourceCurve`, so a hand-typed formula fails the build.

### 1.2 CSS — `styles.css`, `match.css` and `ui.css` are GENERATED

> **Do not edit `styles.css`, `match.css` or `ui.css`.** They are build products. `npm run
> build` — which `npm run check` runs after the tests — overwrites all three from `src/css/`.
> Every hand edit to them is silently destroyed on the next build. Each generated file opens
> with a `GENERATED by scripts/build.mjs — do not edit` banner naming its sources.

The CSS source of truth is `src/css/`: small, layered, heavily commented files, concatenated by
`scripts/build.mjs` into the three stylesheets `index.html` already requests. The bundle list in
that script is an explicit array, never a directory read, so the output is byte-for-byte
deterministic and the cascade order is a reviewable decision rather than an accident of
filenames. Block comments are stripped from the generated files (~12.3 KB gzip of rationale);
line structure is preserved.

The three-file split and their names are fixed by `index.html`, which the design layer does not

everything above them.

Hard constraints kept: vanilla ES modules, no framework, no bundler, no runtime dependency,
works as static files from `dist/`. The CSS concatenation is the only build step, and `dist/`
is still plain static files.

## 2. Render architecture (what replaced `render()`)

The old model was `app.innerHTML = …; bind();` on every state change. It is gone. There is no
global render function and `#app.innerHTML` is never assigned after boot.

* **Mount once, patch in place.** Each screen is created once at boot, appended to `<main>`, and
  exposes `{ el, mount(), show(route, {focus}), hide(), escape?(), focusSearch?() }`. Navigation
  toggles `hidden`; it never rebuilds.
* **Delegated events.** `delegate(root, 'click', { actionName: fn })` in `src/core.js` attaches
  **one** listener per screen and dispatches on `data-action`. There are no per-card closures.
* **Prebuilt search index.** `src/cards.js` builds 1,134 lowercase strings once at module load.
  Filtering is a single `indexOf` pass (`queryCards`).
* **Windowed grids.** Both the Codex grid and the deck pool render only the rows intersecting
  the scroller plus two rows of overscan, recycling row elements. Tiles are also
  `content-visibility: auto` with `contain-intrinsic-size`.
* **Focus, caret and scroll survive.** The search `<input>` is a stable node that is never
  re-created. `router.selfNav` tells screens that a route change came from their own filter
  update, so `show()` does not steal focus back to the `<h1>` mid-keystroke.

### 2.1 The layout invariant the windowing depends on

`#app` is `height: 100dvh; overflow: hidden` and each screen owns its own scroll container.
**Do not remove this.** An unconstrained scroller reports `clientHeight` equal to its full
content height (≈54,000 px for 1,134 cards), the "visible rows" calculation then sizes the pool
to the entire canon, and the node count silently returns to ~22,000. Below 900 px the app
deliberately reverts to page scrolling and the grids get an explicit `height: 68dvh` instead.

### 2.2 Measured before / after (headless Chromium, 1600×1000, `dist/` over HTTP)

| | Before | After |
| --- | --- | --- |
| DOM nodes, Codex at rest | 35,154 elements (measured from the produced HTML string) | **1,446 total nodes on the page**, ~35 card tiles live |
| HTML rebuilt per keystroke | 1,194,477 bytes | **0** — no node is created while typing |
| Event listeners attached per render | ~1,200 closures via 12 `querySelectorAll` passes | **0** — one delegated listener per screen, attached at mount |
| Characters accepted by the search field | **1**, then focus was destroyed | all of them; caret position preserved mid-string (verified by inserting `X` at offset 2 of `lance` → `laXnce`) |
| `input` event → painted grid (2 rAF) | 300–900 ms budgeted | **14.7–21.7 ms** measured |
| Deck screen nodes | — | 1,391 |
| Codex nodes at 1280×800 / 390×844 | — | 1,234 / 1,040 |

Budget targets from the brief §7 that are met: ≤2,500 DOM nodes in the Codex, keystroke→caret
≤16 ms, keystroke→filtered grid ≤100 ms.

## 3. Routing

Hash routing, no server config. `src/core.js → router`.

| Route | Screen |
| --- | --- |
| `#/` | Front door |
| `#/codex` | Codex browser |
| `#/codex?d=6&f=Weapon&r=Rare&c=4-6&q=lance&sort=cost` | Filtered Codex |
| `#/codex/D06-WEAPON-S03-06` | Codex with the detail drawer open on that card |
| `#/deck` | Doctrine construction |
| `#/match` | Active match (mulligan / board / result are phases, not routes) |
| `#/rules` | Primer + glossary |

* Navigations (view change, opening a card, changing a structural filter) **push**.
* Refinements (typing in search) **replace**, so Back does not walk backwards through keystrokes.
* `#/match` with no match in progress redirects to `#/deck` and announces why.
* Query keys are short and stable: `d` division, `f` family, `r` rarity, `c` cost band,
  `q` query, `sort`. Values equal to `all` / `''` are omitted from the URL.

**Two invariants the router itself guarantees.**

1. **`emit()` is idempotent.** Chromium fires *both* `hashchange` and `popstate` for a
   same-document fragment navigation, so both listeners are registered (between them they cover
   every browser) and `emit()` compares the parsed route — view, id, and an order-independent
   serialization of the query — against the current one and returns if nothing changed. One Back
   press therefore runs each `onChange` listener exactly once. Never assume a route handler is
   cheap or idempotent by itself; on `#/codex` it is a pass over 1,134 cards and a live-region
   announcement.
2. **`parse()` never throws.** A hash is user input. A malformed percent escape in the id
   segment (`#/codex/%E0%A4%A`) falls back to the raw segment rather than letting
   `decodeURIComponent` throw inside the handler.

**Query values are user input and screens must validate them.** `parse()` hands back whatever
was in the URL, as strings. `src/screen-codex.js` checks every value against the set it may
belong to (`divisionById` for `d`, the family/rarity/cost/sort lists for the rest) and falls back
to `all`/default before anything reaches the store. This is not defensive decoration: a throw
inside the route handler aborts the rest of it, and the shell — nav highlight, `<title>`,
`body[data-view]` — is written *before* `screens[view].show()` for the same reason. Both together
are what stop `#/codex?d=NOPE` from leaving the app describing the previous screen.

**A screen's `show()` may be called with a route it is already displaying.** Typing in the Codex
search applies the filter, then rewrites the URL with `replace: true`, which comes straight back
as a route change. `show()` compares the validated query against the store and skips the
recompute when they match, so a keystroke costs exactly one pass over the canon rather than two.

**The disclosure.** 231 of the 1,134 cards (20.4%) belong to a family the engine resolves to no
numeric effect — Operative, God, Ruler, World. Their canonical rules text reads like a mechanic
("Division matching is preserved as metadata"), so every surface that shows a card says so
outright instead: `data-blank="true"` on the tile, `⚠ NO MECHANICAL EFFECT` in the `.cardNote`

rather than adding a block of its own **because a permanent extra line makes tiles overlap the
row below** — see §5 and §8.4.

* Rules text is **not** on the tile at grid density. It lives in the detail drawer and the
  inspector only.
* State classes: `.selected` (+ `aria-selected`/`aria-pressed`), `.isDisabled`
  (+ `aria-disabled="true"`, **never** the `disabled` attribute — the control stays focusable so
  its reason is reachable), `.hasNote`.
* `data-rarity` drives frame construction, `data-division` drives the ink/edge/deep tokens.
* Densities: base = Codex tile, `.compact` = deck pool / mulligan, `.handCard` = hand dock.
  These are the **only three rendered card widths**, so the compositor holds at most three
  scaled rasterisations of the atlas.

### 4.5 Pre-match, difficulty and seeds

```
.dialogPanel.preMatchPanel
  .eyeline + h2.dialogTitle#preTitle
  .preGrid > .preBlock > h3 + ul            ← "Your doctrine" / "The match"
  h3.preSubhead
  .tierList[role=radiogroup] > button.tierBtn[role=radio][.active] > strong + span
  label.field.preSeed > span + input#seedInput + small.analysisCaption#seedHelp
                                               + small.fieldError.seedNote#seedNote[data-kind=error|warn|ok]
  .dialogActions
```

The match bar's `button.barSeed` copies `state.seedCode`. The debrief carries
`.endSeed > h3 + p + .endSeedRow > code.seedCode + .btn + .btn`, where the second button
re-launches the same seed. `#seedNote` is the pre-match verdict on a pasted code and has
three states, distinguished by sentence and not by colour alone: `error` (it will not
decode), `warn` (it decodes but was recorded with a different doctrine, or is a legacy code
that recorded none) and `ok` (it will replay exactly). No surface may claim a code
reproduces a match without saying that the doctrine has to match too — it does not.

`button.barRules` exists **only** when the match is running a balance override
(`state.rules.digest !== CANONICAL_RULES.digest`), and is absent from every shipped build.
When it is there it is not decoration: a player comparing the board against the Rules screen
has no other way to learn why the numbers disagree, so the chip names the ruleset, its title
counts the values that differ, and activating it opens a table of every one of them. The
debrief carries the same label as a `.endStat`. A build that runs an override silently is a
build that lies to its player. `.hudBias` in the rival HUD prints the difficulty tier and states
that the rival drafts from the full canon to mirror the player's profile — it is **not** a
division bias, and any copy claiming a three-division rival is stale.

### 4.6 Notifications (four channels, never mixed)

| Channel | DOM | Used for |
| --- | --- | --- |
| Inline field error | `p.fieldError` + `aria-describedby`/`aria-invalid` on the control | deck legality ("needs exactly 30") |
| Contextual reason | `p.laneReason` inside `.laneSide[data-legal="no"]`, and `.cardNote[data-note="warn"]` on the hand card | every `getPlayability` rejection. Never a toast, never a `title` attribute |
| Toast | `.toastHost > .toast[.toast-warn][.leaving] > .toastText + .toastUndo + .toastClose` | transient confirmations, undoable actions. `role="status"`, max 3, 4 s (7 s with Undo), pauses on hover/focus |
| Dialog | `.dialogHost > .dialogScrim + .dialogPanel` | destructive confirmation only. `role="alertdialog"`, focus trapped, Escape cancels, the destructive action is **not** focused by default |

**Dialog lifetime is owned by `closeDialog()` in `src/ui.js`, and it is bounded by navigation.**

* Escape is handled by **one** capture-phase listener installed at `mountUI()`, not per panel. A
  per-panel listener stops working the moment focus is anywhere else in the document, and a
  dialog whose Escape does not work is a dialog you cannot leave.
* The route handler in `app.js` calls `closeDialog(null)` on **every** route change. A dialog
  belongs to the screen that opened it, and browser Back is a route change no dialog can
  intercept. Without this, Back over the pre-match dialog left the panel painted and the scrim
  swallowing every click on whatever screen you landed on, unrecoverable short of a reload.
* While a dialog is open the global key handler returns immediately, so `g`+letter, `/` and `?`
  cannot navigate the shell out from under it.
* Callers must treat a `null` result as a cancel. Every current caller does.

Live regions: `#livePolite` (`role="status"`) and `#liveAssertive` (`role="alert"`), both
`.srOnly`. The match log is `role="log" aria-live="polite" aria-relevant="additions"` and is set
`aria-busy="true"` while a whole rival turn is appended, so the screen reader gets the
**summary first** ("Rival turn resolved: you took 7 Core damage, lost 2 units. Core 13 of 20.")
rather than twenty queued announcements.

`.term` is a real `<button>` that opens `.popoverHost > .popover`. Terms resolve against
`src/glossary.js`.

## 5. Custom properties the JS sets or the CSS must provide

**Set by JS (do not rename):**

| Property | Set on | Meaning |
| --- | --- | --- |
| `--art-x`, `--art-y` | any card / unit / hero art host | atlas tile column and row |
| `--division` | tiles, rail buttons, deck entries, detail panel, hero | the raw canon colour, for continuity with the existing stylesheets |
| `--cols` | `.codexScroller`, `.vgrid` | live column count for the windowed rows |
| `--motion-scale` | `<html>` | `1` or `0`; the single switch every animation multiplies by |

**Provided by the token layer, consumed by JS-driven components.** All of these live in
**`src/css/01-tokens.css`** (the division tiers in `src/css/02-divisions.css`) — not in
`ui.css`, which is a generated file. Renaming any of them breaks a component:

* Type: `--font-sans`, `--font-mono`, `--t-900 … --t-200`. **`--t-200` is 12 px and is the hard
  floor** — nothing in the component layer computes below it.
* Space: `--sp-1 … --sp-8` (2/4/8/12/16/24/32/48).
* Surface: `--surface-1/2/3`, `--line`, `--line-hi`, `--edge-gold`, `--text`, `--text-dim`.
* Semantic: `--danger`, `--ok`, `--warn`, `--info`, `--focus`.
* Motion: `--dur-instant/fast/base/move/beat/scene`, `--ease-out/in/move`.
* Division tiers: `--div-ink`, `--div-edge`, `--div-deep`, mapped from `[data-division="1…21"]`.
  `--div-ink` is the only tier permitted for text (the raw canon colours span 2.35:1 to 19.05:1
  on navy; the ink tier spans 10.0–11.2:1).
* Card geometry: `--tile-h` (272px), `--art-h` (128px base, 96px compact, 58px hand).

**`--tile-h` has a mirror in JS and the two must be read together.** The windowed grids position
rows absolutely at `rowIndex × ROW_H`, so the JS pitch has to clear the tallest tile the CSS can
produce, or rows overlap:

| CSS | JS mirror | Current |
| --- | --- | --- |
| `--tile-h` + row gap | `ROW_H` in `src/screen-codex.js` | 272 + 14, pitch **300** |
| compact tile height | `rowH` passed to `createVGrid` in `src/screen-deck.js` | pitch **288** |

The pitch is deliberately larger than `--tile-h` + gap: a tile whose contextual-note slot runs to
two lines measures up to 292px, and the 231 cards carrying the *no mechanical effect* disclosure
(§4.2) reach that whenever they also carry a note. If the design layer gives the disclosure a
treatment that costs no line, both pitches can come back down.

## 6. The animation seam

`src/motion.js` is the only file that knows how an engine event becomes pixels. It is 190 lines
and has exactly two inputs.

```js
const motion = createMotion({
  resolve,     // (event) => HTMLElement | null   — provided by the screen
  skipHost,    // element that hosts the Skip control
  onDone,      // optional
});

motion.consume(newEvents, { side: 'player' });
motion.cancel();          // also bound to the Skip control and to any pointerdown
motion.running;           // boolean
```

**The governing rule, and the reason this is safe:** the board is patched to its final state
*before* `consume` is called. In `src/screen-match.js`:

```js
function applyMatch(next, { bulk = false, animate = true } = {}) {
  const previousSeq = lastEventSeq;
  match = next;
  paint({ bulk });                                          // FINAL STATE FIRST
  const fresh = (match.events || []).filter(e => e.seq > previousSeq);
  lastEventSeq = match.eventSeq || 0;
  if (animate && fresh.length) motion.consume(fresh, { side: 'player' });   // decoration on top
}
```

Consequences that are load-bearing: skipping can never produce a different board (skip only
cancels decoration); input is never queued behind a timeline; a mid-timeline click is
interpreted against the true state.

### 6.1 Event shape consumed

`state.events` is append-only, `seq` gapless and monotone. The envelope is
`{ seq, round, turn, type, side, lane, cardId, uid, amount, text, … }`; the full catalogue of 29
types is in `docs/engine-api.md` §3.1. `motion.js` handles:

`core-damage` · `damage-prevented` · `play` · `combat-clash` · `combat-strike` ·
`unit-destroyed` · `trap-sprung` · `deploy-trigger` · `spell-resolve` · `response-copy` ·
`deity-convert` · `android-automate` · `ritual-resolve` · `law-restricted` · `virus-delay` ·
`power-change` · `unit-moved` · `fatigue` · `draw` · `resource-gain` · `match-end`.

**Unknown types are ignored, never errors.** The engine may add more at any time.

Two behaviours worth knowing:

* `combat-strike` (raw intent) is folded into the following `core-damage` for the same lane, so
  the chip reads `7 raw → −3` rather than an unexplained 3. `damage-prevented{source:'Armour'}`
  renders as `armour held 4`.
* Priority order (from `engine-api.md` §9) is encoded in the `PRIORITY` map. When a resolution
  produces more events than the 2,400 ms budget can show at the 48 ms floor, the **low-priority
  tail is dropped**, not the Core damage.

### 6.2 Motion tokens and reduced motion

`MO-3` cap 2,400 ms; `MO-6` reduced cap 800 ms and 80 ms per event. Reduced motion is a single
switch: `document.documentElement.dataset.motion` plus `--motion-scale`, honoured from the very
first animation. `prefers-reduced-motion` is the default; the user-facing **Reduce motion**
toggle in the match bar overrides the OS preference in both directions and persists to
`localStorage: collectiveCodex.settings.v1`.

Under reduced motion, *movement* collapses but *information* survives: damage chips, prevented
chips, counters, event order and the Skip control all remain. Only `transform`, `opacity` and
`outline` are animated (MO-1).

FX classes the designer may restyle: `.fxHost`, `.fxChip.fxChip-danger|ok|strike`, `.fxCoreHit`,
`.fxCoreDrop`, `.fxPrevent`, `.fxTrigger`, `.fxLand`, `.fxClash`, `.fxDraw`, `.fxScene`,
`.skipTimeline`.

## 7. Keyboard and focus

* Skip link is first in tab order. Route change moves focus to the new view's `<h1 tabindex="-1">`
  — **except** when the route change was self-initiated (`router.selfNav`), which is what keeps
  the search caret alive.
* The Codex grid is **one tab stop**: roving `tabindex` over a virtualised pool. Arrow keys,
  Home/End, PageUp/PageDown, Enter/Space to open, `a` to add to the doctrine, `[`/`]` to step the
  detail panel.
* Match: `1–9,0` select a hand card · `←/→` **with focus in the hand** move through it, which
  is the only keyboard route to an eleventh card and beyond · `a/s/d` and `←/→` elsewhere move
  the lane cursor · `Enter` commits
  (a live hand selection always beats an armed end-turn) · `e` arms End turn · `i` inspect ·
  `b` read the board aloud · `l` focus the log · `Esc` closes / disarms / clears.
* Global: `/` focus search · `?` key sheet · `g` then `c/d/b/r/h`.
* No single-key shortcut fires while focus is in an `input`/`select`/`textarea`.
* **No global shortcut fires while a dialog is open.** The dialog layer owns Escape (§4.6);
  every other chord returns early.
* The armed end-turn state has **no timeout**. It clears when the player disarms it, selects a
  hand card, targets a lane, or confirms — reading three lanes of projected damage takes longer
  than any timer would allow, and a confirmation that silently re-arms is worse than none.
* Focus ring is uniform: `outline: 2px solid var(--focus)` + `outline-offset: 2px` +
  `box-shadow: 0 0 0 4px var(--bg)`. It is never removed. Card tiles use `overflow: visible` so
  they cannot clip their own ring.

**Verified:** a complete match — deck, pre-match, mulligan, 6–8 rounds of play across all three
lanes, and a result — driven with the keyboard alone, twice (a Victory on veteran and a Defeat
on sovereign), with zero console errors.

## 8. Working on the CSS

### 8.1 The one rule: edit `src/css/`, never the three root stylesheets

`styles.css`, `match.css` and `ui.css` in the repository root are **build products**, regenerated
from `src/css/` by `scripts/build.mjs`. `npm run check` runs the tests and then the build, so an
edit made directly to one of them survives exactly until the next `npm run check` and then
vanishes without a word. Each generated file opens with a banner saying so and naming its
sources; §1.2 has the full source-to-bundle map.

Workflow:

```sh
$EDITOR src/css/07-card.css     # the real source
npm run build                   # regenerates styles.css / match.css / ui.css
npm run check                   # tests + build; must be clean before committing
```

Both the sources and the generated files are committed — the generated ones so `dist/` can be
produced from a checkout without a build step, the sources because they are what anyone actually
reads. If the two disagree, the sources win; run the build.

To add a stylesheet, add the file to `src/css/` **and** to the correct array in the `cssBundles`
map in `scripts/build.mjs`. The arrays are explicit lists, not directory reads: a new file that
is not listed simply never ships, and the cascade order stays reviewable. The three output names
are fixed by `index.html`, which the design layer does not own.

Comments are free. Block comments are stripped from the generated files (they cost ~12.3 KB
gzip, a sixth of the transfer budget), so `src/css/` carries the rationale and the built artifact
carries the rules. Write the reasoning down.

### 8.2 Where each concern lives

| If you are changing… | Edit |
| --- | --- |
| a colour, a type step, a spacing step, a duration | `src/css/01-tokens.css` — the single token layer |
| a division's ink / edge / deep tier or band | `src/css/02-divisions.css` |
| the typefaces or the metric-matched fallbacks | `src/css/00-fonts.css` (+ the font files in the `scripts/build.mjs` copy list) |
| the card tile at any density | `src/css/07-card.css` — but read §5 first: `--tile-h` has a JS mirror |
| buttons, fields, chips | `src/css/05-controls.css` |
| toasts, dialogs, popovers | `src/css/06-notify.css` |
| the board, units, hand | `src/css/2x-match-*.css` |
| a screen's layout | `src/css/30-codex.css`, `31-deck.css`, `32-static.css` |
| animation or the reduced-motion cut-out | `src/css/33-motion.css` (and §6 — the JS multiplies by `--motion-scale`) |
| breakpoints | `src/css/34-responsive.css` |
| forced-colors / prefers-contrast / focus fallbacks | `src/css/35-a11y.css` — loads last so it wins |

### 8.3 Selector collisions to be aware of

The DOM deliberately reuses some long-standing class names (`.codexCard`, `.cardArt`,
`.divisionRail`, `.topbar`, `.primary`, `.battleUnit`, `.supportChip`, `.laneUnits`,
`.laneSupports`, `.deckList`) so the established visual language still lands. Several older rules
are **descendant-typed** (`.deckList>button>b`, `.battleUnit>span`, `.supportChip span`) and can
match different children than they were written for. Target the classes listed in §4 rather than
element positions.

### 8.4 Open for the visual pass

* **The disclosure badge.** 231 cards (20.4% of the canon) are marked *no mechanical effect*
  (§4.2). The JS writes it into the existing `.cardNote` slot and sets `data-blank="true"` on the
  tile, because a dedicated block cost a second line and made tiles overlap the row below. A
  proper treatment driven off `[data-blank]` that costs no layout height would let §5's row
  pitches come back down — and would let the hand tile, which is a fixed 244px, show both the
  disclosure and the playability reason instead of clipping the second line.
* **Rarity frame construction (VD-20).** `src/css/07-card.css` ships a structural stub — hairline
  / double hairline / heavier division edge, driven by `[data-rarity]`. The corner brackets,
  guilloche and foil sweep are open.
* **Board tinting (VD-23)** is a 3% wash placeholder; the seam is the only gold-edged horizontal.

## 9. Assumptions about `match-engine.js` and `deck-store.js`

These are read-only to the UI layer and imported as a **namespace** (`import * as engine`) so a
renamed or added export cannot break module linking:

Read: `LANE_NAMES`, `DECK_SIZE`, `STARTING_CORE`, `MAX_UNITS_PER_LANE`, `DRAW_PER_REFRESH`,
`ENTITY_FAMILIES`, `DEFAULT_DIFFICULTY`, `resourceCurve`, `effectiveCost`, `getPlayability`,
`laneThreat`, `createMatch`, `mulligan`, `playCard`, `completePlayerTurn`, `decodeSeed`;
from `deck-store.js`: `loadDeckIds`, `saveDeckIds`, `buildStarterDeck`, `buildRivalDeck`,
`deckProfile`, `castableTurn`, `filterDeckPool`.

Read from state: `phase`, `round`, `turnCount`, `active`, `winner`, `endReason`, `seedCode`,
`difficulty`, `eventSeq`, `events[]`, `log[]`, `stats.{player,rival,coreHistory}`,
`players.{player,rival}.{core,hand,deck,discard,resources,turnNumber,lanes[].{units,supports}}`,
`unit.{uid,card,power,basePower,weaponBonus,weaponUsed,exhausted,deployedTurn,infected}`,
`support.{uid,card,disabled,counters,faceDown}`.

The UI **never** mutates match state; every transition goes through an engine function and the
returned object replaces the previous one.

Rules the UI is now explicit about, because the player cannot infer them:
deployment fatigue (`JUST DEPLOYED ⏾` chip, spoken on play, stated in the pre-match dialog and
the primer), Core armour (`min(⌈raw/4⌉,3)` — the seam shows the landed number and the animation
shows `7 raw → −3`), regroup, draw 2 per refresh, and deck-out fatigue (`.countBtn.pressure`).

The rival deck is built with `buildRivalDeck(cards, playerDeck)` over the **full canon**. The
previous three-division `buildStarterDeck` pool was a 96/4 structural handicap.

## 11. Where this work is weakest

Stated plainly, because a reviewer will find these anyway.

1. **Two windowed-grid implementations.** `src/screen-codex.js` has its own inline windowing
   (it also carries roving focus and the detail drawer) and the deck pool uses `src/vgrid.js`.
   The maths is duplicated. They should be one module.
2. **Row height is a magic number in three places.** `ROW_H = 300` in `src/screen-codex.js`,
   `rowH: 288` passed to `createVGrid` in `src/screen-deck.js`, and `--tile-h: 272px` + a 14px
   gap in `src/css/07-card.css`. The JS pitches are deliberately larger than the CSS tile so a
   two-line note cannot make rows overlap (§5), but nothing enforces the relationship. Reading
   `--tile-h` back via `getComputedStyle` at measure time, and measuring a real tile once, would
   be honest; it is not done.
3. **`src/css/01-tokens.css` carries colour and type decisions that are not mine to make.** The
   division ink tiers, the semantic palette and the type scale are transcribed from the brief
   because the components need *something*. They are a placeholder token layer, not a design.
4. **The Codex grid's `role="grid"` is only partly virtualised-correct.** `aria-rowcount` and
   `aria-rowindex` are set, but rows outside the window genuinely do not exist, so a screen
   reader's "browse the whole grid" model depends on the scroller doing the right thing. It
   tests fine in practice; it is not the same as a fully rendered grid.
5. **The seam is honest but shallow.** It shows landed damage per lane and whether a lane is
   open. It does not yet explain *why* (which unit, which prevention). The tooltip and the
   `b` read-board sentence carry that load.
6. **Motion is chips and pulses, not FLIP.** `card-play` does not fly from the hand slot to the
   lane; `unit-destroyed` does not fracture. The seam, the budget, the priority ordering and the
   skip semantics are all in place — the choreography named in brief §4.3 is not.
7. **No automated regression on the perf budget.** The numbers in §2.2 were measured by hand
   with Playwright scripts in a scratch directory. `scripts/perf-check.mjs` (PF-10) does not
   exist, and the transfer budget in brief §7 is currently exceeded (95.0 KB gzip against a
   70 KB budget) with nothing failing the build over it. Note that `scripts/build.mjs` strips
   comments from the CSS bundles but copies the JS verbatim, so the rationale in `src/**.js`
   ships to every visitor.
8. **`tests/presentation.test.mjs` runs against a hand-written DOM stub, not a browser.** It
   covers `h()`, `delegate()`, the router's parse/serialize/emit contract and `createVGrid`'s
   index maths, which is where the shipped bugs were. It does not cover layout, focus order or
   anything that needs real CSS — those are still verified by hand with Playwright.
8. **Mobile match layout is a stack, not a design.** At ≤900 px lanes stack vertically and the
   page scrolls, which contradicts the one-viewport rule that the desktop layout meets. It is
   usable and has no horizontal overflow at 390×844, but it is the least considered surface.
