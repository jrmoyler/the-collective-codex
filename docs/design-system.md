# The Collective Codex — design system

**Owner:** visual design / design systems
**Audience:** anyone editing CSS in this repository, and the reviewer checking that it holds up.
**Status:** implemented. Every number in this document was measured in Chromium against the
built `dist/`, not asserted.

This is the third handover in the chain: `docs/polish-brief.md` says what to fix,
`docs/ui-contract.md` says what DOM exists, this document says what the pixels are and what
rules a future contributor has to keep.

---

## 0. The five decisions everything else follows from

1. **The typefaces are self-hosted and the product makes zero external requests.**
2. **Colour never identifies a division.** The glyph and the zero-padded index do. Colour is
   atmosphere, and at grid scale it is collapsed to **six doctrine bands**.
3. **The card frame is the hero object**, and rarity is expressed as frame *construction* —
   never glow, never particles, never a colour upgrade.
4. **The 80×80 artwork is a crest, not a photograph.** It is drawn 1:1 in a mat, at one of four
   discrete sizes, and nothing in the stylesheet magnifies its softness.
5. **12px is a hard floor.** Density is managed by removing fields, never by shrinking type.

## 1. Source layout and the build

The CSS is authored as seventeen small files under `src/css/` and concatenated by
`scripts/build.mjs` into the three stylesheets `index.html` already requests. `index.html` is
not owned by this layer, so the number and the names of the stylesheets are fixed; the split
below is the design decision.

```
styles.css   foundation   00-fonts  01-tokens  02-divisions  03-reset
                          04-shell  05-controls  06-notify  07-card
match.css    the board    20-match-board  21-match-units  22-match-hand
ui.css       screens      30-codex  31-deck  32-static
             + the tail   33-motion  34-responsive  35-a11y
```

Four rules for the cascade:

* **The order is an explicit list in `scripts/build.mjs`, never a directory read.** The output
  is byte-for-byte deterministic; `npm run build` twice produces identical files (verified by
  md5).
* **`ui.css` loads last, so `34-responsive` and `35-a11y` win over everything.** Preference
  fallbacks (`prefers-contrast`, `forced-colors`) belong there and nowhere else.
* **Never edit `styles.css`, `match.css` or `ui.css` directly.** They are generated and carry a
  `GENERATED by scripts/build.mjs` banner. Edit the source and rebuild.
* **Block comments are stripped from the built files.** The sources carry ~1,000 lines of
  rationale; shipping it costs 12.3 KB gzipped, a sixth of the whole transfer budget. Line
  structure and indentation survive, so the artifact is still readable — the reasoning lives in
  `src/css/` and in this document. No minifier, no preprocessor, no dependency: it is four
  `String.replace` calls, and it is safe here because no string or `url()` in this codebase
  contains a comment opener and CSS block comments cannot nest.

Shipped size: **16.3 KB gzipped for all three stylesheets** (7.1 + 4.3 + 4.8), 70.9 KB raw, plus
53.7 KB of fonts. The sources are 1,861 lines across 17 files, none longer than 285. The file
this replaced was one line of 12,838 characters.

There are **no** defensive overrides left. The block `ui.css` used to carry — two
`backdrop-filter: none !important`, a `content: none !important` for a decorative radial blob, a
`transition: none` to undo an all-property transition on 1,134 tiles, an `opacity: 1` to undo a
2.2:1 disabled state, a `@media (hover:hover)` wrapper around a sticky hover, and a
`grid-row: auto` to unstick a leaked `grid-row: 1/3` — is gone, because every declaration it was
fighting was deleted at source. The only `!important` declarations that remain are
`[hidden] { display: none }` and the reduced-motion switch, which is required to be a blanket
override by MO-7.

## 2. Type

### 2.1 Two families, self-hosted, zero network

`assets/fonts/space-grotesk-latin-var.woff2` (22,288 B) and
`assets/fonts/jetbrains-mono-latin-var.woff2` (31,432 B) — **53.7 KB, two files**, against a
budget of 60 KB and two files. Both are Latin-subset *variable* files covering weight 400–700,
so three Grotesk weights and two Mono weights cost two requests rather than five.

The Google Fonts `@import` that used to be `styles.css:1` is deleted. It was render-blocking and
cross-origin, it contradicted the README's offline claim, and in a sandboxed browser it failed
with `ERR_CONNECTION_RESET` — which meant the product had **never actually been seen in its
intended typeface** by anyone. Verified after the change: two `woff2` responses, both `200`,
both same-origin; zero requests to any external host on every route including a full match.

### 2.2 No-shift swap

`font-display: swap` plus a metric-matched fallback face per family. The override values were
measured, not guessed — Chromium canvas `fontBoundingBoxAscent/Descent` and the advance width of
a representative sentence, at 100px:

| | ascent | descent | sentence advance |
|---|---|---|---|
| Space Grotesk | 0.98em | 0.29em | 3181.23px |
| Arial (fallback target) | 0.91em | 0.21em | 2985.11px |
| **`size-adjust`** | | | **106.5%** = 3181.23 / 2985.11 |
| `ascent-override` | 92% = 0.98 / 1.065 | `descent-override` 27.2% | `line-gap-override` 0% |

| | ascent | descent | advance per char |
|---|---|---|---|
| JetBrains Mono | 1.02em | 0.30em | 0.600em |
| fallback mono | 0.93em | 0.24em | 0.602em |
| **`size-adjust`** | | | **100%** |
| `ascent-override` | 102% | `descent-override` 30% | `line-gap-override` 0% |

Measured effect: the string `Aureate Chimera` at 16px is 126.63px in Space Grotesk, **128.74px**
in the metric-matched fallback (1.7% off) and 120.95px in raw Arial (4.5% off). The overrides cut
the swap's width error by 2.7×, and `line-gap-override: 0%` removes the line-box height change
entirely, which is the dominant CLS source.

### 2.3 Scale

16px root. **`--t-200` = 12px is the floor and nothing computes below it.**

| Token | px | Line | Tracking | Use |
|---|---|---|---|---|
| `--t-900` | 36 | 1.05 | −0.03em | screen `h1` |
| `--t-800` | 28 | 1.1 | −0.02em | panel titles, Core numeral, debrief verdict |
| `--t-700` | 22 | 1.2 | −0.01em | card name in the detail drawer |
| `--t-600` | 18 | 1.35 | 0 | lead paragraph, door titles |
| `--t-500` | 16 | 1.55 | 0 | body, rules text |
| `--t-400` | 14 | 1.5 | 0 | secondary body, **card name on a tile** |
| `--t-300` | 13 | 1.4 | 0.02em | dense data, chips, log lines |
| `--t-200` | 12 | 1.35 | 0.08–0.18em | **floor** — uppercase mono labels only |

Rules: uppercase + tracking is reserved for `--t-200` labels and nav. Card names, rules text and
log lines are sentence case. Every numeral that can change is `font-variant-numeric: tabular-nums`.

**Verified:** a DOM sweep of every element with text (own text nodes or `::before`/`::after`
content) across `#/`, `#/codex`, `#/deck`, `#/rules` and an open detail drawer, at 1600×1000,
1280×800, 390×844 and 800×500 — **zero declarations render below 12px**. The nine sub-12px
declarations listed in the brief's A-26 table lived in `styles.css` and `match.css` and are gone
with those files' old contents. The two 11px hard-coded sizes the interaction layer had left in
`.unitChip` and `.supportMeta` are also gone; that density is now bought by shortening the chip
text, not by shrinking it.

Two rules that are easy to break:

* **`--line` and `--line-hi` may never be the only carrier of meaning.** They are at 1.4–1.9:1 and
  fail the 3:1 non-text floor on purpose — they are structure. If a border says *legal*,
  *selected*, *disabled* or *this is the boundary of a lane*, it uses `--line-strong`, a semantic
  colour, or a band/division tier, all of which clear 3:1.
* **The resource triad is fixed forever and is never a division accent.** Each also carries its
  letter and a distinct pip shape (`▮` bar / `◆` rhomb / `●` disc), so the triad survives
  greyscale and every form of colour blindness.

### 3.2 The division palette — derived, not designed

The canon hexes in `card-canon.js` are **locked** and are not edited. The display palette is
derived from them:

```
hex -> linear sRGB -> OKLab -> OKLCH
pin L per tier, clamp C to the tier's band, keep H untouched
gamut-map back to sRGB by reducing C by 3% until in range

tier   OKLCH L   chroma clamp     role
ink      0.800   [0.055, 0.150]   text and glyphs on navy
edge     0.620   [0.070, 0.165]   1px borders, art mats, rules
deep     0.340   [0.045, 0.110]   fills only — never text
```

### 3.3 Doctrine bands — why the grid is calm

Colour **cannot** identify a division even in principle. After hue analysis, five pairs sit
within 4° of each other — ZenFlow and Quantum Ledger are **0.3°** apart, which is to say
identical. So colour is demoted to the third signal, behind the glyph and the two-digit index,
and at grid scale twenty-one hues are collapsed to **six categories the eye can actually hold**.
Each band's hue is the circular mean of its members' hues.

The `--band-N` **rule tier** sits at OKLCH L 0.545 — deliberately one step below `--div-edge`.
It is what a card *frame* wears, which makes it the single loudest colour decision in the Codex,
so it is tuned to clear the 3:1 non-text floor on every surface and go no further. Navy still
wins the grid.

Not the name, not the rules text, not the cost chips, not the footer — all of which were
coloured before. At grid scale the eye sees navy cards with six kinds of edge.

### 3.4 The one gap in this system, and a bug it uncovered

Four components — `.battleUnit`, `.deckEntry`, `.spreadSeg`, `.doorHero` — are built **without**
a `data-division` attribute. They try to pass the raw canon hex in `--division` instead
(`src/screen-deck.js:148` and `:189`, `src/screen-match.js:242`, `src/screen-static.js:47`), and
those raw values are exactly the ones that span 2.35:1 to 19.05:1, so they could not be used as
authored anyway.

**For three of them the value never arrives.** `h()` applies a style object with
`Object.assign(el.style, …)` (`src/core.js:16`), which silently drops custom properties. Verified
in the browser: `.deckEntry`, `.spreadSeg` and `.battleUnit` carry **no `style` attribute at all**
and `getPropertyValue('--division')` returns the empty string. The division-coloured deck spread
has never rendered, in this build or the one before it. `.doorHero` is the exception —
`src/screen-static.js:47` uses `setProperty` and works. `paintTile()` is likewise unaffected.

The same bug has a much louder consequence that is not about colour at all: it also drops
`--art-x` and `--art-y` on `.battleUnit`, so **every unit on the board draws atlas tile (0,0)** —
the same artwork, every time, for both sides. See §10.1.

The CSS side is written to be correct the moment either half is fixed: inside an
`@supports (color: oklch(from #123456 l c h))` guard the three tiers are derived from
`--division` **live** — same pinned lightness, same chroma clamp, hue preserved — so a raw canon
hex is normalised on arrival exactly as the frozen tokens above were. Until then the fallback hue
is a neutral steel, which reads as a deliberate absence of accent rather than as a fake gold. On
an engine without relative colour the block is skipped entirely and the neutral `:root` tokens
apply.

## 4. Space, line, radius, elevation

* **Space** is a 4px scale: `--sp-1…8` = 2, 4, 8, 12, 16, 24, 32, 48. No arbitrary values.
* **Line** is one weight: 1px, everywhere. Depth comes from line *colour*, never line thickness.
  The two exceptions are both semantic: a 2px inner ring for lane legality and the focus ring,
  and a 2px outer edge that marks a Legendary frame.
* **Radius** is `--r-0: 0` for panels, chips and the grid; `--r-card: 12px` for cards only;
  `--r-pill` for resource pips only. The product's structure is orthogonal and the card is the
  only soft thing in it — which is also why the card's *inner* bezel is square.
* **Elevation** is a four-step ladder and **no element carries more than two shadow layers**:

| Token | Value | Used by |
|---|---|---|
| `--e-flat` | `none` | rails, the seam, disabled cards, exhausted units |
| `--e-raise` | `0 1px 0 rgba(255,255,255,.035), 0 2px 8px rgba(0,0,0,.45)` | every card, every board unit, the count buttons |
| `--e-lift` | `0 8px 24px rgba(0,0,0,.5)` | toasts, popovers, the inspector, the board bed |
| `--e-scene` | `0 24px 64px rgba(0,0,0,.6)` | modals only |

The depth model is deliberately identical across Codex, deck pool, hand and board: a card is
`--surface-2` on a 1px band edge at `--e-raise`, on a `--surface-1` panel, on `--bg`. The board
adds one step below — `--pit` — so the bed reads as an object you are looking down at.

**Exactly one ambient light effect exists in this product**: a single cool vignette at the top of
`body`. There are no other radial gradients, no glows, no orbs, no blobs. The decorative radial
blob behind every division tile is deleted.

### 5.1 Rarity is frame construction

The canon is nearly uniform across rarities — Common 233, Rare 235, Uncommon 231, Legendary 219,
Epic 216 — so a jackpot treatment would fire on a fifth of the product and would be a lie. Rarity
escalates *structure*; it never escalates the palette. The whole frame — edge, bezel and
brackets — is one colour, the doctrine band.

| Rarity | Frame | Mark |
|---|---|---|
| Common | 1px neutral hairline (`--line-hi`). The quietest 233 cards stay quiet. | `○` |
| Uncommon | 1px band edge + 2 top corner brackets (15px arms) | `◔` |
| Rare | + inner bezel hairline | `◑` |
| Epic | + 4 brackets + an engraved guilloche in the nameplate (5% repeating gradient) | `◕` |
| Legendary | 2px band edge, band bezel, 4 brackets in the band's *ink*, guilloche, and a single-pass foil sweep on hover/focus | `●` |

Corner brackets are eight 2px gradient arms on one pseudo-element — the same element that draws
the bezel — so the whole construction costs zero extra DOM. The foil sweep is `transform` and
`opacity` only, **one pass on intent**, never a loop, 12% maximum opacity, `display: none` under
`forced-colors`, and disabled under reduced motion.

### 5.2 The crest

The source art is 80×80 (`docs/card-art-recovery-audit.md`), displayed at 56–160px. It is
treated as icon-grade art the frame flatters:

* **`.cardArt`'s *content box* is a 1:1 square of exactly `--art-size`,** centred by symmetric
  padding, and the atlas is addressed in px against that content box:
  `background-size: 21S × 54S`, `background-origin/clip: content-box`,
  `background-position: −art-x·S, −art-y·S`. A second, empty background layer with
  `background-clip: border-box` is what lets the alcove colour fill the whole shelf while the
  artwork stays inside its mat. Before this change the tile was stretched to the card's aspect by
  roughly 1.2×; it is now never stretched at all.
* **`--art-size` is a small discrete set,** so the compositor holds a countable number of atlas
  rasterisations instead of one per fluid tile width:

| `--art-size` | Atlas raster | Used by |
|---|---|---|
| 160px | 3360 × 8640 | detail drawer, front-door hero, and the single-column Codex tile below 560px |
| 128px | 2688 × 6912 | Codex grid tile, deck pool, mulligan |
| 96px | 2016 × 5184 | hand dock |
| 56px | 1176 × 3024 | board unit |

  **Two of these are card densities** (128 and 96), against a cap of three. The previous build
  had no cap at all: `.cardArt` was fluid, so its raster width changed with every viewport and
  every column count — and the tile was stretched to a different aspect ratio at each one.
* **Nothing sharpens, blurs, upscales or shadows the art.** The entire treatment is a 1px
  `--div-edge` mat and a soft inner vignette to hide the upscale edge.
* When the atlas has not decoded (`html[data-art]` ≠ `ready`) the fallback is the division glyph
  at 40% of the crest on its own ground — never a broken image box, never an empty rectangle.

### 5.3 Densities

Each density **removes a field**; none shrinks type below 12px.

| Class | Width | `--art-size` | Fields |
|---|---|---|---|
| `.codexCard` | fluid ≥176px | 128 | stamp, crest, name, costs, power |
| `.codexCard.compact` | ≥168px | 128 | the same, tighter gaps and a 13px name |
| `.handCard` | 148 × 244 | 96 | the same **plus** the contextual playability note |
| `.battleUnit` | 122 | 56 | crest, name, effective power, status chips |
| `.detailArt` / card-lg | 232 plate | 160 | the complete record, in the drawer |

### 5.4 States

Never opacity alone, never colour alone.

| State | Signals |
|---|---|
| hover (pointer devices only) | band-ink frame + `--surface-3` fill. Wrapped in `@media (hover: hover)` so it cannot stick on touch |
| selected | 2px gold frame + gold bezel + **a folded gold corner tab** |
| disabled | dashed frame + `--line` + greyscaled crest + dimmed name + the reason in `.cardNote`. `aria-disabled`, never the `disabled` attribute — the control stays focusable so its reason is reachable |
| note | `.cardNote` in `--ok` / `--danger` / `--info` by `data-note`, always with text |

`.codexCard` carries **no transition**. A card that changes state must read as changed on the
next frame, not 200ms later — and an all-property transition across 1,134 elements was one of the
measured problems in the brief.

## 6. The board

* The play surface is a **pit** (`--pit`); the bed is `--surface-1` inside a 1px `--edge-gold`
  frame at `--e-lift`. That single step of depth is what makes the board read as an object.
* **Three lanes are full-height columns** divided by one 1px `--line-strong` rule that runs
  unbroken from the rival HUD, through the seam, to the player HUD. A lane is read top to bottom.
* **Territory:** rival tint is cool (`rgba(167,192,222,.03)`), player tint is warm
  (`rgba(227,183,83,.034)`), and both **deepen toward the seam**, so the middle of the board is
  visibly where the pressure is. That gradient pair plus the seam is the entire "whose side is
  this" system — no textures, no perspective, no 3D tilt.
* **The seam is the only gold-edged horizontal element on the board.** It prints the damage that
  will *land*, not raw board power.
* **Whose Core is this** is answered before the label is read: the rival's lit segments are
  `--info` blue, yours are `--ok` teal, and either bar turns `--danger` with a `CRITICAL` word
  below 6.
* **A board unit does not wear a division-coloured frame.** Ten units in three lanes each with
  its own hue is the rainbow problem moved from the Codex to the board. The frame is neutral
  (`--line-strong`), the division is a single 3px rule on the leading edge, and the crest carries
  the rest.
* **Status is text + icon**, never opacity: `JUST DEPLOYED ⏾`, `EXHAUSTED ⏾`, `INFECTED ☣`,
  `WEAPON +2 ⚔`, `GUARD ⛨`, `FLYING ⌃`. Exhausted also takes a dashed frame, so it survives
  greyscale.
* **A face-down rival trap is a card back**, not a greyed card: gold hairline, gold hatch, and it
  stays present in the accessibility tree.

## 7. Motion

Tokens: `--dur-instant 60 · fast 120 · base 200 · move 280 · beat 420 · scene 520`, with
`--ease-out`, `--ease-in`, `--ease-move`, `--ease-snap`.

The binding rules, and where they are enforced:

| Rule | How this stylesheet keeps it |
|---|---|
| **only `transform` and `opacity` animate** | grep the sources: no keyframe or transition touches width, height, top/left, box-shadow, background-position or border-colour |
| **nothing loops** | the Legendary foil sweep is `1` iteration on hover/focus; there is no other repeating animation in the product |
| **nothing exceeds `--dur-scene`** | except the foil sweep, which is an intent-driven flourish, not a state change |
| **no entrance animation on the grid** | MO-9: the Codex grid appears, it does not cascade in |
| **reduced motion collapses movement, not information** | one switch (`--motion-scale`) and one media block. Damage chips, prevented chips, counters and the Skip control all survive; they arrive in place instead of travelling |

The vocabulary is small on purpose. `.fxChip` rises 16px and fades (damage, prevention, raw
strike). `.fxCoreHit` shakes the HUD ±3px, twice, **only when the damaged side is the player**.
Everything else is a 2px outline flare in the semantic colour on the element the event names —
the eye is told *where* before it is told *what*. `.fxClash` adds a 7px lunge; `.fxLand` a 0.94→1
scale. That is the whole list, and every entry encodes a state change that has already happened
to the board.

## 8. Rules a contributor must follow

1. **Never edit `styles.css`, `match.css` or `ui.css`.** Edit `src/css/*` and run `npm run build`.
   If you add a file, add it to the ordered list in `scripts/build.mjs` — a directory read would
   make the output non-deterministic.
2. **No new colour, size, duration or shadow outside `01-tokens.css`.** If a component needs one,
   the token is missing.
3. **No declaration may compute below 12px.** Density is bought by removing fields.
4. **A border that carries meaning uses `--line-strong` or better.** `--line` and `--line-hi` are
   structure and fail 3:1 on purpose.
5. **Colour is never the only signal.** Division = glyph + index. Rarity = word + pip. Resource =
   letter + shape. Damage = sign + icon. Status = text chip + icon. Ownership = position + label.
6. **Never re-derive a division colour by hand.** Regenerate the tiers with the algorithm in §3.2
   and paste the result into `02-divisions.css`. The canon hexes are locked.
7. **Only `transform` and `opacity` may be animated,** and every animation must encode a state
   change. If it exists to look busy, it is cut.
8. **Maximum two shadow layers per element,** from the four-step ladder.
9. **`--art-size` must stay a small discrete set.** Adding a fifth value adds a full atlas
   rasterisation to the compositor.
10. **Banned, in review:** purple-blue default gradients, glassmorphism or backdrop blur as a
    surface, floating decorative blobs, generic icon-trio rows, hero → 4-up metrics → 3-column
    features rhythm, a third typeface, skeleton shimmer, emoji as UI iconography, centred
    marketing copy on any gameplay screen.
11. **Every visual decision must survive the sentence "this makes the board state faster to
    read."** If it cannot, it is decoration and it is cut.

### Known weaknesses

* **Three components render with no division accent at all** (§3.4), because the interaction
  layer's `h()` drops inline custom properties. The CSS is written to light up the instant that
  is fixed, but today they are neutral, and a neutral steel is a choice I made *because* I could
  not make the real one — not because it is better.
* **`--art-size` is four values.** Two are card densities (128, 96), which is inside the brief's
  cap of three; 160px serves the detail drawer, the front-door hero and the single-column phone
  tile, which never coexist, and 56px is the board unit. Four rasterisations of a 2 MB atlas is
  still four rasterisations.
* **The Codex geometry constants are still duplicated** between `src/screen-codex.js` (`ROW_H`,
  `GAP`, `MIN_TILE`) and `30-codex.css` (`--tile-h`, the row gap). Change one without the other
  and rows overlap. The CSS side is commented; the duplication itself is not fixed.
* **At 390px the Codex renders one column**, which is the JS column calculation, not the
  stylesheet. The tile compensates by stepping the crest up to 160px, but two columns would be a
  better use of the width.
* **The mobile match layout is a stack that scrolls**, which contradicts the one-viewport rule the
  desktop layout meets. It is usable, has no horizontal overflow at 390×844, and every piece of
  information survives — but it is the least considered surface in the product.

## 10. What this layer needs from the interaction layer

Three markup/JS changes were deliberately **not** made here, because `app.js`, `index.html` and
`src/**/*.js` are not owned by this layer. Each is small, each is worked around, and each would
delete a workaround.

**10.1 — `h()` silently drops custom properties, and one consequence is a visible art bug.
(One line.)**
`src/core.js:16` is `else if (k === 'style' && typeof v === 'object') Object.assign(el.style, v);`
`Object.assign` onto a `CSSStyleDeclaration` cannot set a custom property, so every
`h(tag, { style: { '--…': … } })` call site produces an element with **no `style` attribute at
all**. Three components are affected: `.deckEntry` (`src/screen-deck.js:148`), `.spreadSeg`
(`:189`) and `.battleUnit` (`src/screen-match.js:242`). `.doorHero` and `paintTile()` are fine —
they use `setProperty`.

**The important one is `.battleUnit`.** That call site passes `--division`, `--art-x` *and*
`--art-y`, so every unit on the board renders atlas tile (0,0) — the same creature, both sides,
every lane, in this build and the one before it. Confirmed by reading back the computed values on
a live board: `--art-x` and `--art-y` are empty strings and `background-position` is `0px 0px` on
every unit. No stylesheet can work around this; the value has to reach the element.
Suggested fix:

```js
else if (k === 'style' && typeof v === 'object')
  for (const [prop, val] of Object.entries(v))
    prop.startsWith('--') ? el.style.setProperty(prop, val) : (el.style[prop] = val);
```

**10.2 — those same four elements want `data-division="N"`, not `--division`.**
Even once 10.1 lands, a raw canon hex is the wrong input: those values span 2.35:1 to 19.05:1 and
seven of them fail 4.5:1. `data-division` selects the frozen, measured tier set in
`02-divisions.css` **and** the doctrine band, which the raw colour cannot supply because a band
is a function of the division *index*, not its hue. One extra `dataset` key on each of the four
call sites removes the entire `@supports` derivation block from `02-divisions.css`.

**10.3 — a `<link rel="preload" as="font" type="font/woff2" crossorigin>` for the two WOFF2 in
`index.html`.** Not required — the fonts are same-origin, 22 KB and 31 KB, and are discovered
while `styles.css` is parsed, which is the first stylesheet — but preloading them would start
both requests a round trip earlier and remove the last theoretical swap window. `index.html`
already preloads the atlas the same way; this is the same two lines:

```html
<link rel="preload" as="font" type="font/woff2" crossorigin href="assets/fonts/space-grotesk-latin-var.woff2">
<link rel="preload" as="font" type="font/woff2" crossorigin href="assets/fonts/jetbrains-mono-latin-var.woff2">
```

**Not requested, on purpose:** nothing about the card tile's 12-node structure, the class
contract in `docs/ui-contract.md` §4, or the geometry constants. The frame anatomy in §5 is built
entirely from the nodes and pseudo-elements that already exist, and it needs no new element.
